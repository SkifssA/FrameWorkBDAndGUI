# FrameWorkBDAndGUI

Фреймворк для быстрого создания десктоп-приложений на **PyQt6** с интеграцией базы данных (**Turso / libSQL**) и системой модулей. Проект предоставляет готовый каркас: формы, виджеты, API-слой для работы с БД и SDK для расширения функциональности собственными модулями.

## Возможности

- 🖥️ **GUI на PyQt6** — темы оформления (`core/ui/theme.py`), готовые формы, виджеты и элементы ввода.
- 🗄️ **Слой данных** — работа с Turso/libSQL через `SQLapi` и `Turso` (HTTP/API-обёртка).
- 📦 **Модульная система** — бизнес-логика выносится в модули (`module/bc`, `module/awh`), список модулей описан в `project.yaml`.
- 🧱 **Базовые классы** — семейство `EmptyAvi` / `EmptyObj` (`core/empty`) задаёт контракты «объект → форма → действие».
- 🛠️ **Генераторы кода** — CLI-команды для создания классов, файлов и модулей (`main.py`).

## Структура проекта

```
├── core/
│   ├── DB/            # Слой работы с базой данных (SQLapi, Turso)
│   ├── createClass/   # Генераторы: классы, табы, модули
│   ├── empty/         # Базовые классы объектов и действий (obj, avi, api)
│   ├── fabric/        # Фабрики
│   ├── package/       # Пакетные утилиты (AiohttpPkg, ActionDispatcherPkg и др.)
│   ├── sdk/           # Публичный фасад для модулей
│   ├── type/          # Типы и события
│   └── ui/            # Формы, виджеты, элементы ввода, тема
├── module/            # Пользовательские модули (bc, awh)
├── tools/             # Вспомогательные скрипты (.cmd)
├── main.py            # Точка входа: CLI-генераторы + запуск приложения
└── project.yaml       # Конфигурация списка модулей
```

## Установка

Требования: Python 3.10+

```bash
pip install -r requirements.txt
```

Зависимости: `PyQt6`, `libsql_client`, `nest_asyncio`, `pyyaml`, `aiofiles`, `beautifulsoup4`.

## Запуск

```bash
# Запуск приложения
python main.py launchApp

# Создание нового класса/таба
python main.py createClass

# Создание нового модуля
python main.py createModule
```

Либо через `LAUNCH APP.cmd` в Windows.

## Разработка

Рекомендуемый стиль (см. `CONVENTION_MODULE_NAMING.md`): единая схема именования модулей и классов, camelCase для методов UI-слоя, явные связи между классами вместо магической вложенности.
