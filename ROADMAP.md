# Дорожная карта проекта

Общая цель: модульная платформа, где каждый модуль — самостоятельное приложение.
Интерфейс строится на метаданных (schema-driven UI), фронтенд — HTML + CSS + HTMX + Alpine.js,
визуальная часть полностью на HTML/CSS, JS используется минимально.

Иконки для модулей: https://icons8.ru/icons/fluency-systems-regular

---

## Этап 1. Рефакторинг: убрать «макаронный код»

**Цель:** привести ядро к нормальному функционированию, разделить слои и ответственность.

- [✓] Разделить core-классы: метаописание (Dmeta/attrMetaShema), данные (Pkg), логику (Logic) и точки входа (@Oper).
- [✓] Убрать дублирование: единый источник метаданных для формы, листа и фильтров.
- [✓] Ввести единый контракт модуля (см. CONVENTION_MODULE_NAMING.md): загрузка модуля через реестр, а не ручные импорты.
- [✓] Диспетчер действий (`/api/action/{tab}/{method}`): whitelist только @Oper-методов и сеттеров.
- [✓] Покрыть базовыми тестами загрузку модуля, диспетчер и рендер метаданных.

**Результат:** UI дергает только @Oper-методы и сеттеры; Pkg/Logic недоступны из UI.

## Этап 2. Начальный интерфейс (App Shell)

**Цель:** приложение ощущается как приложение, а не как сайт. Единый каркас + фрагменты.

### 2.1 Выбор приложения
- [✓] Стартовый экран: список модулей (иконка + название) из реестра модулей.
- [✓] Переход в выбранное приложение и обратно без перезагрузки страницы (HTMX-фрагмент в область контента).

### 2.2 Главное меню приложения
- [✓] Главное меню с вкладками/табами модуля (генерируется из метаданных модуля).
- [✓] Активный таб, состояние запоминается в URL (#/module/tab) — прямой доступ к разделу.

### 2.3 Карточка и лист (только просмотр, без редактирования)
- [✓] **Лист (список):** таблица записей, колонки берутся из Dmeta; клик по строке открывает карточку.
- [✓] **Карточка:** read-only форма, поля генерируются из attrMetaShema (тип, порядок, группировка).
- [✓] Навигация лист ↔ карточка через HTMX-фрагменты внутри App Shell.

**Результат:** пользователь выбирает приложение → видит меню → смотрит лист → открывает карточку.

- [ ] **Обязательные поля:** флаг `required` в метаданных → звёздочка/подсветка в UI + серверная валидация в @Oper/сеттерах.
- [ ] **Иконки модулей:** поле `icon` в описании модуля; отображается на экране выбора и в главном меню.

## Этап 4. Фильтры

**Цель:** фильтрация листа по метаданным (filterMetaShema / Dmeta).

- [ ] Панель фильтров над листом: поля-кандидаты для фильтрации определяются метаданными.
- [ ] Типы фильтров по типу поля: текст (содержит), число (диапазон), дата (период), справочник (выбор).
- [ ] Параметры фильтра передаются на сервер и применяются к запросу (SQL-шаблоны остаются на сервере, клиент шлёт только значения).
- [ ] Сохранение активного фильтра в URL — возможность поделиться состоянием листа.

## Этап 5. Коллекции в основной форме

**Цель:** к карточке основной формы добавлять связанные коллекции (табличные части).

- [✓] Метаданные описывают связи: основная форма → N коллекций (каждая со своим Dmeta).
- [✓] В карточке коллекции отображаются как вкладки/секции-таблицы под основной формой.
- [✓] CRUD коллекции — через @Oper-методы модуля (по одному стандартному набору операций).
- [ ] На этом этапе добавляется редактирование основной формы и коллекций (после read-only версии из Этапа 2).
